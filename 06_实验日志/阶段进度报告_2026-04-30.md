# 电力政策知识库阶段进度报告

生成日期：2026-04-30

## 一、当前定位

当前项目已经从“资料文件夹”推进为一个早期工程版的电力政策知识库。它的核心目标是：围绕电力市场、交易规则、中长期、现货、辅助服务、省内、省间、绿电、计量结算等主题，对国家级、省级、监管局、交易中心、电网公司等公开政策资料进行定向采集、文本提取、结构化整理、搜索和 RAG 问答。

当前系统不是全网通用爬虫，而是“白名单来源 + 候选发现 + 定点采集 + 文本提取 + 结构化入库 + 搜索/RAG”的知识库流水线。

### 2. 官方政策采集

已经支持从白名单来源中发现和采集政策资料，包括：

- 国家能源局
- 国家发展改革委
- 省级能源局、发改委、工信厅
- 国家能源局派出监管机构
- 北京、广州等电力交易中心
- 国家电网、南方电网、内蒙古电力等电网相关来源

现阶段采用低频、定向、白名单采集，不做绕过式反爬。

### 3. 文本提取与 OCR

已经支持：

- HTML 正文提取
- PDF 内嵌文本提取
- 扫描型 PDF 的 OCR
- 处理后文本统一写入 `03_处理后文本`

这些处理后文本是全文检索、知识切片和 RAG 的基础。

### 4. 清洗与结构化

已经完成多类字段清洗：

- 标题清洗
- 发布机构清洗
- 采集来源机构回填
- 发布日期提取
- 文号抽取
- 省份/适用地区归一
- 市场主题标注
- 来源类型、权威等级、有效状态整理

文号字段已经进入台账和规则清单，用于后续版本识别、引用关系和规则体系梳理。

### 5. 去重与候选筛选

当前去重主要包括：

- 原文链接去重
- 待采集链接去重
- 候选池 URL 标准化
- 标题异常识别
- 低质量候选过滤

后续需要增强正文 hash 和相似度去重，以适应 1w+ 规模。

### 6. 规则清单

已生成规则清单，用于从“政策文件列表”进一步转向“电力交易规则库”。

规则清单包含：

- 规则名称
- 文件标题
- 发布机构
- 采集来源机构
- 发布日期
- 文号
- 省份
- 市场主题
- 来源类型
- 权威等级
- 有效状态
- 原文链接
- 本地文本路径

### 7. 政策关联关系

已根据正文中的明确引用建立政策关系。当前策略偏保守：

- 有明确文号引用才建立关系
- 有明确规则名称和引用语境才建立关系
- 避免自己引用自己
- 避免把未来政策当作旧政策

搜索页中已经可以展示“明文引用”和“被后续引用”关系。

### 8. 知识切片

已将政策正文拆分为知识切片。

当前切片规则：

- 默认每片约 450 字
- 最小切片 80 字
- 长文本拆分时保留 60 字重叠
- 尽量按段落、章节、条款边界切分
- 每片保留标题、机构、日期、文号、省份、主题、权重、原文链接、本地路径

切片用于 RAG 检索和细粒度问答。

### 9. 搜索页面

- 支持关键词搜索

### 10. 网页快照

为降低官网链接失效风险，已新增本地网页快照机制：

- 生成目录：`05_输出成果/网页快照`
- 每条政策生成一个快照 HTML
- 快照页展示政策元数据
- 快照页保留官网原文链接
- 快照页链接本地原始 HTML/PDF
- 快照页链接处理后文本
- 搜索页中原来的“本地文本”入口已替换为“网页快照”

此后搜索结果中，官网链接用于访问在线原文，网页快照用于本地留证。

## 五、当前不足

1. 数据量还小，距离 1w+ 仍有较大差距。
2. 去重仍以 URL、标题、文号为主，正文相似度去重还没完成。
3. 标题和机构清洗仍需人工抽查。
4. OCR 质量需要继续评估。
5. RAG 仍是轻量原型，没有接入更强的语义向量库。
6. 公众号、财经新闻、电力咨询机构资料尚未正式入库。
7. 网页快照已改为截图式证据，但仍不是包含完整外部 CSS/图片资源的全站离线镜像。

## 六、下一阶段建议

优先级建议如下：

1. 扩大来源覆盖，继续补充省级、监管局、电力交易中心、电网公司来源。
2. 批量跑候选发现和回填，提升政策台账数量。
3. 增加正文 hash 和相似度去重。
4. 抽样人工核验标题、日期、机构、文号、OCR 质量。
5. 优化截图快照：补齐少数文本兜底条目，并评估截图体积、清晰度和长期归档策略。
6. 做一个更完整的搜索页面交互版本，例如结果预览、快照预览、RAG 问答入口。
7. 官方政策稳定后，再接入公众号、财经新闻和咨询机构解读资料，并单独设置较低权威等级。

## 七、阶段判断

当前项目已经具备完整闭环：

```text
来源清单 → 候选发现 → 待采集链接 → 正式采集 → 文本提取/OCR → 元数据清洗 → 规则清单 → 政策关系 → 知识切片 → 搜索页/RAG → 网页快照 → 人工核验/GitHub
```

从工程完成度看，目前可以视为一个可运行的早期版本。后续重点不再是“能不能跑通”，而是：

- 扩数据规模
- 提高清洗准确率
- 加强去重
- 完善人工核验闭环
- 提升搜索和 RAG 的可用性
