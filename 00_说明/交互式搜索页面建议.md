# 交互式搜索页面建议

后期建议做一个本地交互式 HTML 搜索页面，形态可以接近轻量搜索引擎。它不应该太早做成复杂系统，最好在全文检索脚本稳定之后再做。

## 一、为什么需要

当前 CSV、Excel 和命令行脚本适合建设阶段，但不适合长期查询使用。知识库资料量超过 50 条后，人工翻表会越来越慢。

交互式页面可以解决：

- 快速输入关键词搜索政策
- 按省份、主题、来源类型、权威等级、有效状态过滤
- 直接查看标题、发布日期、发布部门和原文链接
- 展示命中说明和排序得分
- 对官方政策、监管规则、交易规则、解读资料做明显区分
- 后续接入 RAG 问答时保留引用来源

## 二、建议先做的页面能力

第一版只做搜索，不急着做复杂问答：

- 一个搜索框
- 省份筛选
- 主题筛选
- 来源类型筛选
- 权威等级筛选
- 有效状态筛选
- 结果列表
- 原文链接
- 本地文本预览
- 导出搜索结果 CSV

## 三、页面结果建议展示字段

每条结果建议展示：

- 文件标题
- 发布部门
- 发布日期
- 省份
- 原始适用范围
- 来源类型
- 市场主题
- 权威等级
- 有效状态
- 命中说明
- 原文链接

省份筛选说明：

- 页面筛选项不直接使用 `南方区域`、`华中区域` 等区域标签。
- 区域类文件会映射到相关省份，例如 `南方区域` 映射到广东、广西、云南、贵州、海南。
- 结果卡片仍保留原始适用范围，例如 `适用范围：南方区域`，避免丢失政策适用层级。

排序默认采用：

```text
相关性 + 省份匹配 + 主题匹配 + 权威等级 + 有效状态 + 时间权重
```

## 四、阶段建议

阶段一：本地静态 HTML 搜索页

- 由脚本生成 `search_index.json`
- HTML 直接读取本地 JSON
- 不需要后端服务
- 适合个人本地使用和快速验证

阶段二：本地轻量服务

- 用 Python 提供本地搜索接口
- 支持全文文本片段预览
- 支持更复杂排序
- 可以接入日志和评测

阶段三：RAG 问答页面

- 在搜索结果基础上生成回答
- 必须显示引用来源
- 官方原文优先，解读资料只能辅助
- 支持“原文优先 / 最新优先 / 权威优先 / 解读优先”等模式

## 五、当前结论

建议后期做交互式 HTML 页面，而且它会成为知识库真正好用的入口。

但当前阶段应先完成：

- 资料量稳定到 100 条左右
- 元数据核验一轮
- 全文检索脚本稳定
- 搜索排序评测稳定

做到这些后再做 HTML 页面，效果会更扎实。
